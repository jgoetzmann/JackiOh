# JackiOh — Review File

Two audits, run by an agent that does not fix anything, only reports. **Part A** audits `SPEC.md` against the three source documents and against itself. **Part B** audits the implementation against `SPEC.md` and `BUILD.md`. Run A before any build work and again whenever SPEC.md changes. Run B at every milestone gate in BUILD.md and before release.

## 0. Rules for the reviewer

- You are the reviewer. Do not edit code or the spec. Produce findings and a verdict.
- Every finding needs evidence: a file path with line numbers, or a SPEC section number plus a quoted phrase of at most 15 words, or a test name and its output.
- Severity: **BLOCKER** = a rule, card, or invariant is wrong or missing; **MAJOR** = a required test, ruling, or acceptance item is absent, or a spec statement is ambiguous enough that two implementers would diverge; **MINOR** = wording, numbering, cross-reference.
- Verdict: any BLOCKER → **FAIL**. Any MAJOR with no BLOCKER → **FAIL-MAJOR** (build may continue on that milestone but the next gate is blocked). Otherwise **PASS**.
- Do not accept "it works when I play it" as evidence for a rule; a named passing test is evidence, a manual trace against a fixture state is evidence, a claim is not.
- Report format at the end of this file. Findings are numbered A-1…, B-1….
